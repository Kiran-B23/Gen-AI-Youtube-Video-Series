# Formats

Spoken pace ≈ **2.7 words/second** (162 wpm) for budgeting; reels are delivered brisker (~3.0 w/s, the winners' pace). Runtime = words ÷ 2.7. Keep a 10% buffer.

## 1. Reel / Short (faceless)
_The beat table below is the generic shape. Use the archetype's own beat sheet for the actual script._
**Length:** default **30–60 s** (80–160 words). When the content genuinely needs it (a multi-step mechanism, a full
comparison, a build), go up to **2:50–3:00** (~450–480 words). YouTube Shorts and Instagram Reels both allow up to 3 minutes.
Length must be earned: every extra beat carries new value, never padding. The house benchmark (`references/tokenization-reel.mp4`, 3:14) shows the target depth: every step shown on one running example. Vertical 9:16.
Long Shorts (> 60 s) need a **re-hook every 30–40 s** ("but here's the weird part…", a new open loop, a section colour
change), a progress tracker, and a recap before the CTA.
Voiceover + motion graphics / screen recordings / captions. No presenter.

| Beat | Time | Job |
|---|---|---|
| Hook | 0–2 s | One line + a first frame that already tells the story **on mute**. Curiosity, contrast or a striking number. |
| Stakes / promise | 2–8 s | Why the viewer should care *now*, or what they'll get by the end. |
| Value beats ×2–4 | 8–45 s | One idea per beat. A visual change every 2–3 s. Carry the running example through. |
| Twist / catch | ~45 s | The honest limitation or the surprising turn. It earns trust. |
| Payoff + CTA | last 5–8 s | A one-line takeaway, then a comment question / "save this" / follow. Ideally the last frame loops to the first. |

Tips: one topic, one angle. Cut anything that needs a second sentence to justify. Prefer
"you" over "we". Put the number on screen when you say it.

## 2. Long-form explainer (on camera)
**Length:** 8–15 min → **1,300–2,400 words**. 16:9. Presenter on camera + screen + B-roll.

| Section | Share | Job |
|---|---|---|
| Cold open | ≤30 s | The hook + the payoff promise ("by the end you'll know whether…"). Show, don't introduce yourself. |
| Why it matters | ~10% | The problem or stakes, with a relatable scenario. |
| How it works | ~25% | The mechanism, with **one analogy** and one diagram. |
| Demo / real example | ~25% | Screen capture or a real story. The running example pays off here. |
| The catch | ~15% | Limits, costs, risks, what people get wrong. |
| Verdict | ~10% | Who should use it, who shouldn't, what to do next. |
| CTA | ≤20 s | One clear ask + a comment question. |

Retention devices: **open loops** at about 25% and 60% ("hold on to that, it matters in a
minute"), pattern breaks every 60–90 s (B-roll, graphic, location/angle change), and
chapter titles every 2–3 min.

## 3. Long-form session (on camera + build)
**Length:** 30–60 min → **4,500–9,000 words** (builds have silent work time, so script the
talk track at roughly 60–70% of runtime). 16:9.

| Section | Time | Job |
|---|---|---|
| Hook + outcome | 0–2 min | Show the finished result first, then "let's build it". |
| Concept in 5 | 2–7 min | Only the theory needed to build. One analogy. |
| Build chapters ×3–6 | bulk | Each chapter ends with something **working** on screen. Name the chapter by the result. |
| Gotchas | ~5 min | The errors people will hit and how to fix them. |
| Recap card | 1–2 min | Every step on one screen (screenshot-worthy). |
| Next steps | ≤1 min | Extend it, plus a comment question. |

Also deliver: a **prerequisites** list, a **code/asset list**, and a **checkpoint** after each
chapter (what the viewer should see).

## Choosing the structure inside a format
The **beats inside each format come from the topic's archetype**, not from the tables above (those are
the generic Concept/Launch shape). See `references/archetypes/README.md` to choose one of the 9
archetypes. Each archetype file has its own reel beat sheet, explainer outline and (for Tutorial and
Concept) session variant. Lengths and pace stay as above, adjusted to the winners' pace found in
`inspiration.md`.
